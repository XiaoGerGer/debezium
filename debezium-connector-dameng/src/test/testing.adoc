The floating point tests expose existing discrepancies: high-precision stored values become rounded streamed values, some tiny nonzero values become zero, and negative zero loses its sign during the schema-enabled JSON converter round trip. The raw snapshot Struct preserves negative zero in all five declarations tested; its subsequent JSON decoding does not. The earlier direct LogMiner probe located ordinary fractional rounding in SQL_REDO/MINE_VALUE before connector conversion. The JSON round-trip discrepancy is a separate issue in the current Kafka conversion path, not evidence that DM LogMiner lost the snapshot value. These assertions remain enabled and require the original stored value. A failure is evidence of the data discrepancy; it must not be interpreted as a successful compatibility test. The earlier successful coverage/build results below predate these additional semantic assertions.

The REAL upper-bound fixture follows the https://eco.dameng.com/document/dm/zh-cn/pm/dm_sql-introduction.html[official DM SQL type specification]: its documented range ends at `3.4E38`, below Java's `Float.MAX_VALUE`. The local JDBC driver's `setFloat` rejects the latter as overflow. Such a rejected input is not a connector data-loss result; the regression uses the float representation of the documented bound instead.

Run the engine/database regression with `verify -Pdameng-tests`; run the packaged worker regression separately with `verify -Pdameng-connect-tests,assembly`. Ordinary `test` does not run these Failsafe integration tests. Surefire/Failsafe XML, rather than this implementation inventory, determines the result of each invocation.

=== Large transaction regression

`DamengLargeTransactionIT` is an independent real-database suite for finite large-transaction correctness checks. It covers bounded queue backpressure, an open transaction observed alongside other commits, full and savepoint rollback, and restart from a durable offset in the middle of a transaction. The class reads its limits from JVM system properties; defaults are 10,000 rows, a 512-byte payload, a 300-second timeout, and a 1,000-LSN mining batch. No throughput, memory ceiling, or maximum supported transaction size is implied.

Run only this suite with a disposable Testcontainers database:

[source,shell]
----
TESTCONTAINERS_RYUK_CONTAINER_IMAGE=testcontainers/ryuk:0.12.0 \
  ./mvnw -pl debezium-connector-dameng verify -Pdameng-tests \
  -Dit.test=DamengLargeTransactionIT \
  -Ddameng.stress.rows=10000 \
  -Ddameng.stress.payload.bytes=512 \
  -Ddameng.stress.timeout.seconds=300 \
  -Ddameng.stress.mining.batch.size=1000
----

Set `dameng.hostname`, `dameng.port`, `dameng.user`, and `dameng.password` to use an already prepared DM instance. Increase `dameng.stress.rows` or `dameng.stress.payload.bytes` only after the default correctness run succeeds; record elapsed times and resource usage from the test log separately.

The following extended run executes the complete connector suite, installs the module, and produces its plugin archive, with the stress cases set to 100,000 rows, 512-byte payloads, a 10,000-LSN mining batch, a 600-second wait limit, and a 2 GiB test JVM heap. == Operational safeguards and regression scope

`LogMinerBatchTest` checks cumulative byte and input-row budgets across the complete mining window, including multiple transactions, transaction markers, discarded rows, and SQL continuation pieces. It verifies exact-limit acceptance, preallocation rejection of continuation growth, and rejection of all publication/replay-position APIs after capacity failure. The default limits are 512 MiB estimated bytes and 1,000,000 input rows; they are not a limit on whole-process heap. The limits follow Oracle's configuration conventions, but intentionally do not copy Oracle's optional transaction-discard threshold behavior.

`DamengConnectorConfigTest` covers finite positive socket and initial-snapshot timeouts, the driver's `socketTimeout` mapping, rejection of the ambiguous raw `database.socketTimeout` input, nonnegative statement timeouts, and rejection of unsupported parallel snapshot connections. Real tests must establish that JDBC timeout and connection abort release locks on the deployed DM version, including a snapshot blocked by downstream backpressure. Unit mocks alone cannot establish server-side session termination.

Offsets now require a `capture_scope` signature of database/schema/table include and exclude expressions, `table.ignore.builtin`, and `signal.data.collection`. Older offsets lacking the signature and changes to any signed expression are rejected. This applies to narrowing filters and equivalent-expression rewrites as well as expanding filters. Recovery tests must keep the exact signed values or use a new identity, fresh history and an initial snapshot. Column filters and `snapshot.include.collection.list` do not change the table coverage signature.

Finite budgets do not remove the repeated work caused by a long transaction pinning the scan start. A capacity failure keeps the replay position unchanged and can recur after restart until an operator adjusts the workload or explicitly increases a budget with sufficient heap and retained archives. Archive deletion, prolonged network loss and driver/server failure combinations remain separate fault-injection requirements.
